# 🔒 Security Setup Guide

This document explains how to securely manage your Supabase credentials for both local development and GitHub Pages deployment.

---

## ⚠️ Critical: Rotate Your Current API Key

Your old API key has been exposed in the repository. **You must rotate it immediately:**

1. Go to [Supabase Dashboard](https://supabase.com) → Your Project
2. Navigate to **Settings** → **API Keys**
3. Find your "anon public" key and click **Generate New Key**
4. Confirm the rotation — the old key will be **invalidated immediately**
5. Save your **new anon public key** (you'll need this in the next step)

---

## Local Development Setup

### Step 1: Create `config.local.js`

This file will hold your Supabase credentials for local development.

1. In the project root, create a file named `config.local.js`:

   ```javascript
   // config.local.js
   window.CONFIG = {
       SUPABASE_URL: 'https://YOUR_PROJECT.supabase.co',
       SUPABASE_ANON_KEY: 'your_new_anon_key_here'
   };
   ```

2. Replace:
   - `YOUR_PROJECT` with your Supabase project name (from Dashboard → Settings → General)
   - `your_new_anon_key_here` with your **new rotated anon key** from Step 1

### Step 2: Verify `.gitignore` Includes `.env*` and `config.local.js`

The `.gitignore` file should already contain:

```
config.local.js
.env
.env.local
.env.*.local
```

**Verify it's there:**
```bash
cat .gitignore | grep config.local
```

If not, add it manually.

### Step 3: Test Locally

1. Open `index.html` in your browser
2. Open **Developer Console** (F12)
3. Check for the error message:
   - ✅ **Good:** No error about missing credentials → working correctly
   - ❌ **Bad:** Error about missing credentials → check your `config.local.js`

## GitHub Pages Deployment

For GitHub Pages, you **cannot** include `config.local.js` directly. Instead, use **GitHub Secrets + Actions** to inject credentials at deploy time.

### Step 1: Add Repository Secrets

1. Go to your GitHub repo → **Settings** → **Secrets and variables** → **Actions**
2. Create two new secrets:
   - **Name:** `VITE_SUPABASE_URL`  
     **Value:** `https://your-project.supabase.co`
   
   - **Name:** `VITE_SUPABASE_ANON_KEY`  
     **Value:** Your new anon key

### Step 2: Create GitHub Actions Workflow

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Create config from secrets
        run: |
          cat > config.local.js << 'EOF'
          window.CONFIG = {
              SUPABASE_URL: '${{ secrets.VITE_SUPABASE_URL }}',
              SUPABASE_ANON_KEY: '${{ secrets.VITE_SUPABASE_ANON_KEY }}'
          };
          EOF

      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./
          cname: yoursite.com  # Optional: if using custom domain
```

### Step 3: Commit and Push

1. Commit the workflow file:
   ```bash
   git add .github/workflows/deploy.yml
   git commit -m "Add GitHub Actions deploy workflow with secure credential injection"
   git push origin main
   ```

2. GitHub Actions will now generate `config.local.js` and deploy automatically

## How It Works

```
┌─────────────────────────────────────────────────────────┐
│           index.html / db.js (Public Code)              │
├─────────────────────────────────────────────────────────┤
│ • Loads <script src="config.local.js"></script>         │
│ • Checks window.CONFIG for credentials                  │
│ • If missing, shows console warning but continues       │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│   config.local.js (GITIGNORED — never committed)        │
├─────────────────────────────────────────────────────────┤
│ • Sets window.CONFIG with your credentials              │
│ • Only exists locally or generated by CI/CD             │
│ • Never visible in source control history               │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│     window.CONFIG loaded → CPA module ready             │
│          Supabase client authenticates                  │
└─────────────────────────────────────────────────────────┘
```

## Cleanup: Remove Exposed Credentials from Git History

The old credentials are still visible in your git history. To remove them:

### Option 1: Use `git-filter-repo` (Recommended)

```bash
# Install git-filter-repo
pip install git-filter-repo

# Remove the exposed key from history
git-filter-repo --replace-text <(echo 'sb_publishable_scCLt7VTNyIR-q8QDRPpxQ_4xMubH2Z===>REDACTED')

# Force push (⚠️ WARNING: This rewrites history, all collaborators must re-clone)
git push --force-with-lease
```

### Option 2: Manual Review (Without Rewriting History)

Since `config.local.js` is now gitignored, the credentials won't leak again. However, they're still visible in old commits. This is acceptable if:
- You've rotated the key (so the exposed key is invalid)
- Your repository is public (no additional harm)

## Troubleshooting

### Console shows: "Supabase credentials missing!"

**Cause:** `window.CONFIG` is not defined.

**Fix:**
1. Ensure `config.local.js` exists and has correct credentials
2. Check that `config.local.js` is loaded *before* the CPA module in `index.html`
3. Reload the page (clear browser cache with Ctrl+Shift+Delete)

### "RLS violation" errors in console

**Cause:** Row Level Security policies may not be configured correctly.

**Fix:**
1. Go to Supabase Dashboard → Editor → (select table)
2. Click **RLS** (upper right) and verify policies are enabled
3. Review policies to ensure users can access their own data

### GitHub Pages shows white page / no app

**Cause:** Secrets not injected correctly or workflow failed.

**Fix:**
1. Check GitHub Actions tab → Recent runs for errors
2. Verify secrets are named exactly: `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`
3. Re-run the workflow manually: Actions tab → Workflow name → Run workflow
